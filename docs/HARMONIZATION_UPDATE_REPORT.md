# Harmonization update report (PyroSync 1.4)

Date: 2026-11-15. Scope: the "Recommended, no coverage" plan chosen by the team (coverage work C0, quantities detections + occupied cells, day-level ratio method, stability gate G1, Harmonization tab plus an off-by-default comparison mode in History and AOI Insights, feature branch then preview then main).

Every number in this report comes from files in the repository: `docs/harmonization/AGGREGATE/*/report.md` (generated by `python -m pyrosync.cli harmonize-aggregate --with-events`), the prototype results `docs/harmonization/AGGREGATE/prototype/*_t0*.json (t0 = type 0, t0u = types 0 + unknown)`, and `docs/harmonization/AGGREGATE/aqua_drift_matched_share.json`. "Passes" always means the documented PyroSync project rules. It never means an official or NASA validation.

## 1. Problem being addressed

PyroSync 1.0 to 1.3 calibrates VIIRS to the MODIS scale per matched event (one cell and one overpass). On held-out units it works: run A, Indonesia Aqua–S-NPP, cuts MAE from 3.562 to 0.842 detections per unit. The 1.2 daily-total check showed that this model **does not** reproduce MODIS daily totals. Summed over all VIIRS events it gives 3.79× the MODIS total. Summed over matched events only it gives 0.24×. Because both fail the 0.8–1.25× rule, the calibrated time series was never drawn.

The 1.4 task was to find out why, to test alternatives with a chronological validation, and, only if an alternative passes without weakening the rules, to make it available in the Harmonization tab and as an optional mode in the history pages.

## 2. Root-cause analysis

The event model answers the question "given that both sensors detected this fire, how many MODIS detections go with V VIIRS detections?" Daily totals ask a different question, "how many MODIS detections are there on this day?", which also covers fires seen by one sensor only.

- Only 15.5 % of S-NPP detections (types 0 + unknown; 17.9 % with type 0) are in matched events, and only 37.3 % of Aqua detections are.
- An unmatched VIIRS event with V = 1 still gets M̂ = exp(0.613 + 0.239·ln 2) − 1 = 1.18 MODIS detections, although MODIS mostly records nothing there. That is why the all-events sum is too high.
- The matched-only sum leaves out the 62.7 % of MODIS detections without a partner. That is why it is too low.
- On the day level the relation is nearly proportional: the log-log slope of daily totals is 0.991 (run A, detections), against β = 0.239 at the event level. So aggregation does not preserve the event-level shape, and the event model cannot simply be summed.

A second finding emerged during the reproduction: the matched share collapses after 2023. Aqua left the A-Train in January 2022 and its overpass time has drifted later. Its median daytime acquisition time over Indonesia moved from 05:38–06:11 UTC (yearly medians, 2012–2023) to 06:33 UTC (2024), 07:10 (2025) and 07:47 (2026). With a ±30 min window, the share of S-NPP detections in matched events falls to 7.1 % in 2024, 1.8 % in 2025 and 0.0 % in 2026. The event model therefore cannot be refitted on recent Aqua–S-NPP data at all. The diagnostic in `aqua_drift_matched_share.json` uses the median acquisition time of Aqua events between 03:00 and 08:59 UTC.

A third, smaller finding: 1.3 changed the default type filter from `0` to `0,unknown`, so FIRMS NRT rows (which have no type column) are now included. Run A reproduces the documented 1.0–1.3 numbers exactly with `types=0`: 113,567 units, α 0.613138, β 0.238849, MAE 3.562 → 0.842. With the new default it gives 113,588 units and the same training coefficients. For daily totals the NRT rows matter. With `type=0` only, 2026 days after the SP/NRT switch lose most of their rows, and the 2026 day ratio falls to 0.30×. All 1.4 validation therefore uses `0,unknown`.

## 3. Candidate methods considered

All candidates were fitted on training days and compared on the same held-out days. The prototype (`prototype/proto.py`, run A, split 2019-09-22, 2,536 held-out known days) gave these results:

**Two-part model.** It needs P(MODIS detects | VIIRS event). The only observable label is "matched", and "unmatched" mixes "MODIS did not detect" with "MODIS did not image this cell" (swath gap, cloud, overpass timing). Without verified coverage it underestimates (0.43×). It would become meaningful only with swath and cloud masks (MOD03/MOD14, VNP03/VNP14), which the team decided not to import now (choice C0).

**Coverage-aware aggregation.** Not implemented (C0). Days whose coverage state is unknown for either sensor are excluded, but a known day can still be cloudy.

## 4. Selected method and justification

`pyrosync-aggregate-1.0`: a day-level ratio estimator for AOI daily totals, kept **alongside** the event model and not instead of it.

- It calibrates exactly the quantity the history pages show: one AOI total per UTC day.
- It has one parameter, and its uncertainty can be bootstrapped honestly.
- It needs no matched events, so it keeps working after Aqua's drift.
- More flexible candidates (monthly ratio, day log-log) gave no held-out gain that justifies their extra parameters.
- The diagnostic day-level slope (0.97–0.99 for the Indonesia detection runs) supports proportionality.

## 5. Mathematical derivation

For an AOI, let M_d and V_d be the MODIS (Aqua) and VIIRS daily totals of day d. Let K be the set of days whose coverage state is "detections" or "zero reported" for **both** sensors, T ⊂ K the training days (before the split), and H ⊂ K the held-out days.

- Estimator: **M̂_d = c · V_d**, with **c = Σ_{d∈T} M_d / Σ_{d∈T} V_d**.
- c is the ratio estimator. It is the least-squares fit of M = cV under variance ∝ V, and it reproduces the training total exactly: Σ_T M̂ = Σ_T M.
- **Split.** One rule, whether or not a unit-level run exists: either the configured split date, or the first day of the last `test_fraction` (20 %) of active days in K. An active day has M_d + V_d > 0. Run A splits on 2023-10-27.
- **Rolling origin.** For each calendar year y with at least 30 test days, c_y is fitted on all known days before 1 January y (at least 180 days) and tested on year y. This is an expanding window, as in Tashman (2000).
- **Uncertainty.** A 95 % interval for c from 500 month-block bootstrap resamples of the training days (seed 20261115). Whole months are resampled, so serial correlation within a month is kept (Künsch 1989).
- **Metrics.** On H: MAE, RMSE, MBE and the level ratio Σ M̂ / Σ M, following Hyndman & Koehler (2006).
- **Baselines.** Raw VIIRS (M̂ = V) and a constant equal to the mean training MODIS total. The event model is reported for comparison when a run's events are available.
- **Quantities.** Detections, and occupied cells (grid cells with ≥ 1 detection per day on the run's comparison grid). Each has its own c and its own gate.

**Gate `pyrosync-aggregate-gate-1.0`.** All thresholds were fixed in `aggregate.py` before any run. The 1.2 daily-total rules are kept unchanged, and four stability checks are added:

1. At least 30 held-out days.
2. Held-out level within 0.8–1.25×.
3. MAE and RMSE better than raw VIIRS.
4. MAE and RMSE better than the training-mean constant.
5. At least 3 rolling-origin years.
6. At least 80 % of rolling-origin years within 0.8–1.25×.
7. No rolling-origin year outside 0.67–1.5×.
8. At least 10 held-out high-fire days (MODIS at or above the training 90th percentile) with a total within 0.8–1.25×.

## 6. Data and assumptions

- **Data.** Full FIRMS archive for Indonesia, dataset revision 1: 10,917,537 rows, 2000-11-01 to 2026-11-14.
- **Default filters.** MODIS confidence ≥ 30; VIIRS nominal/high; types `0,unknown`; day and night; 0.1° grid.
- **Assumptions.**
  - The MODIS/VIIRS ratio of AOI daily totals is stable in time. The rolling-origin years test this.
  - Cloud and smoke affect both sensors similarly on a given day, because they overpass close in time.
  - Known-status days are representative.
- **MODIS is a reference scale, not ground truth.** It misses small and obscured fires, and its own errors stay in the target.
- **Valid period.** Only days where both sensors exist: S-NPP from 2012-01-20, NOAA-20 from 2018-04-01. The method is never applied before the VIIRS record starts. Extending it back to 2000–2011 would require MODIS alone and is not done.

## 8. Test methodology

- **Backend unit tests** (`test_aggregate.py`, 6 tests on labelled SYNTHETIC TEST FIXTURES covering five years) check:
  - c = ΣM/ΣV on training days only;
  - the gate passes on a stable relation;
  - doubling MODIS after the split leaves c and the split **identical** (no leakage), while the gate fails on the level check and no line or band is drawn;
  - days without known coverage stay `None`;
  - monthly totals equal the sum of the daily totals;
  - a short history fails the rolling-years check;
  - the endpoints return 200 and reject invalid values with 422;
  - the ZIP contains the aggregate report;
  - original daily series are unchanged.
- **Full backend suite:** 121 passed. The sixth test (a VIIRS series absent from the database returns an "insufficient" gate instead of no gate) was added after the first preview showed that case.
- **Browser checks:** 18 of 18 passed. Flow 18 checks:
  - the gate badge equals the API;
  - the series is withheld when the gate fails;
  - map ratio availability follows the gate, and the regional count equals the API;
  - the History and Insights comparisons are off by default, send no request before the toggle, and their gate equals the API.
- **Full-archive runs:** A, C, D and F via the CLI. Each report lists every check.

|---|---|---|---|
| Raw VIIRS | 7.55 | 754.1 | 1,942.7 |

Run C shows the same pattern: event model 3.75× (all events) and 0.03× (matched only), against 1.07× for the ratio. The matched-only sum is now much lower than the 0.24× reported in 1.2, because the new held-out period (from late 2023) falls in the years when Aqua drift leaves almost no matches.

The event model stays the better tool for its own question (one matched cell and overpass, unit-level MAE 0.842 vs 1.232 for a unit ratio model, 1.2 report). The ratio is the better tool for AOI daily totals. Neither replaces the other.

## 11. Daily and historical validation results

- **Run A detections, rolling origin.** All 14 test years (2013–2026) are within 0.8–1.25×. The range is 0.83× (2024) to 1.22× (2015). In every year the ratio beats the constant on MAE.
- **Run A, high-fire days.** 101 days at or above 289 MODIS detections per day; their total is 0.98× (raw VIIRS 7.45×).
- **Run A, low-activity days.** 1.01×.
- **Run A, monthly totals.** 36 months; total 0.99×; 83 % of months within 0.8–1.25×.
- **Run C.** All 8 years (2019–2026) are within 0.87–1.21×. High-fire days are 1.05×. 90 % of months are within the band.
- **Seasonal.** The month-of-year ratio variant gained only 1 % MAE in the prototype, so no strong seasonal dependence of c was found at Indonesia scale.
- **Regional (Kalimantan, run D).** The total level is fine (1.06×). But 2024 is 0.66× and only 10 of 14 years are in the band, so the gate fails. The low-activity days (2.06×) show that the AOI-wide c over-predicts quiet days in a smaller area. In the app, the regional ratio view of the error map shows, per 0.5° region, where the Indonesia c holds.
- **Per satellite pair.** Aqua–S-NPP and Aqua–NOAA-20 both pass at Indonesia scale. The Terra–S-NPP control fails (years 0.74–1.84×). Terra overpasses about 3 h earlier, so its day totals sample a different part of the diurnal fire cycle, and a single c is not stable. This is the expected behaviour of a negative control.
- **Aqua drift.** The 2024–2026 ratios for run A (0.83, 0.92, 1.04) stay within the band although event matching collapsed in those years. This shows the day-level method is usable after the drift. It is not proof that the drift has no effect; the 2024 value is the lowest of all years.

## 12. Known limitations

- Coverage is **not verified** (C0). Known days can be cloudy or partly imaged, and only unknown-status days are excluded.
- The method calibrates **AOI daily totals only**. The per-cell "ratio index" on the map is c × VIIRS detections of that cell, a visual aid that is not validated per cell.
- Validation passes for **Indonesia-wide detections** with Aqua and S-NPP or NOAA-20. It fails for occupied cells, for Kalimantan, and for Terra. Every other AOI is checked live by the same gate, and small AOIs usually fail.
- The single 2023-10-27 split puts the MODIS collection change (6.0 → 6.1 in 2023) and the 2026 NRT period in the held-out data. They are tested, not corrected.
- Year-level results are correlated (an expanding window shares training data), and the bootstrap interval covers c, not the daily error.
- MODIS is a reference scale. A MODIS-equivalent total is not a "true" fire count.
- FRP is not calibrated by either method.

## 13. Recommendations for future work

1. **Coverage (options C1–C3).** Import swath geolocation and fire/cloud masks (MOD03/MOD14, VNP03/VNP14) for a few seasons and count only cells both sensors imaged cloud-free. This would allow a real two-part model and a coverage-aware ratio. It needs LAADS access, which the development container could not reach.
2. **Aqua end of mission.** When Aqua stops, re-run the rolling-origin check with Terra–NOAA-20 or NOAA-20 alone as the continuity reference.
3. **Regional c.** Fit c per region with partial pooling, and validate per region with the existing regional ratio view.
4. **Occupied cells.** Test a cells-specific non-linear model (the day log-log slope is 1.05–1.10), with the same gate.
5. **Proposal.** Report the passes and the failures together (section 9), with the rules version.
